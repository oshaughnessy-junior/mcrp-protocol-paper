# Review as a distributed workflow

“Please review this paper” is an underspecified work order.

A scientific release may need checks of data custody, execution, statistical design, software, instrument calibration, uncertainty treatment, domain interpretation, ethics, and adversarial alternatives. No single reviewer is guaranteed to cover all of them, and a prose report rarely makes the uncovered scope obvious.

MCRP can represent a review request as an immutable object: exact target release and claims, questions, required competencies, conflict policy, confidentiality, resources, deadline, and completion rule. A coordinator can decompose it into bounded work packages. Execution services reconstruct environments. Statistical reviewers examine models. Data reviewers trace custody and fitness for use. Domain reviewers assess interpretation. Adversarial reviewers search for counterevidence. Each report records its method, evidence inspected, exclusions, and unresolved questions.

Agents are useful precisely where scale overwhelms attention. They can inventory objects, retrieve evidence, run declared procedures, compare versions, monitor dependencies, and draft structured reports. Their outputs should retain delegation, tools, inputs, and limitations. A human may adopt an agent-assisted report only by naming the material examined and accepting responsibility for a stated scope. Agent activity does not manufacture an independent reviewer or satisfy a human-disposition guard.

The assembled result is a coverage view, not an average. Two reports can jointly cover different requirements. Overlap can increase confidence or expose conflict. Missing work remains visible. A coordinator or community policy decides whether the declared completion rule has been met.

Distributed work will produce disagreement, sometimes by design. The next post treats that disagreement as a reusable scientific object instead of noise to be erased by consensus prose.
